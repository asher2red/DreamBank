# Step 05 — P0 사용자 경험 구현 결과

작업일: 2026-10-29 (Asia/Seoul)

## 1. 완료한 사용자 기능

홈과 내 계좌에 로컬 DB의 실제 계좌 데이터를 연결했다. 기본 별칭은 `나의 여유 계좌`, 가상 잔고는 `₩1,000,000,000`이며 `가상 잔고 · 실제 금융 자산이 아니에요.`를 함께 표시한다. 저장된 별칭과 잔고는 두 화면에 동일하게 반영된다.

- 홈: 브랜드·인사말·가상 계좌·오늘의 여유·마음 선택·첫 안내·꿈 보관함 진입.
- 오늘의 여유: 공통 및 네 가지 기분별 메시지 풀, 날짜에 따른 첫 메시지, 같은 풀 안에서 다른 메시지 순환.
- 마음 잔고: 선택 없이 이용 가능. 다른 기분을 선택하면 저장 성공 후 선택 표시와 메시지를 갱신한다. 같은 선택의 반복 제출과 저장 중 추가 제출을 막는다.
- 마음 복원: 오늘 기록만 선택으로 복원한다. 자정과 날짜 변경 후에는 새 날짜의 기록을 재조회한다. 과거 기록은 삭제하지 않는다.
- 계좌 편집: 별칭·가상 잔고를 변경하고 저장 결과를 홈과 내 계좌에 반영한다. 별칭은 1~30 사용자 인식 문자, 잔고는 0~999999999999 정수 원이다.
- 첫 안내: 가상 서비스·기기 저장·삭제 시 손실 안내를 제공하고 확인 상태를 저장한다. 안내를 확인하지 않아도 다른 기능을 사용할 수 있다.
- 앱 소개: 실제 금융 서비스가 아니라는 설명과 기기 저장·편지 공개 규칙을 유지한다.

꿈·편지 편집 및 공유 카드 기능은 이번 단계에 추가하지 않았다. 기존 안내 화면을 유지하고 계획된 P1 단계에서 구현한다.

## 3. 저장·오류·화면 동작

저장 성공을 확인한 뒤에만 마음 선택과 계좌 저장 완료를 표시한다. 마음 저장 실패 시 이전 기분과 메시지를 유지하고 실패한 선택을 다시 시도할 수 있다. 계좌 저장 실패 시 폼과 입력을 유지한다. 계좌 조회와 마음 조회의 오류·재시도를 분리해 다른 기능을 계속 이용할 수 있다.

계좌 편집 중 뒤로가면 변경 내용이 있을 때 계속 작성·버리기를 묻는다. 저장 중에는 필드·저장 버튼과 화면 이탈을 잠근다. 금액은 `1000000`, `1,000,000` 형식을 허용하고 잘못된 쉼표·음수·소수·지수 표기·통화 기호·범위 초과는 거부한다.

기본 글자 크기에서는 실제 글꼴의 금액 폭을 측정해 카드 안에 맞도록 24~40 크기로 조정한다. 시스템 글자를 확대한 경우에는 크기를 강제로 줄이지 않고 가로 스크롤로 전체 값을 유지한다. 화면 읽기에는 가상 잔고 전체 금액을 하나의 라벨로 제공한다. 마음 선택은 Wrap으로 배치한다. 편집 폼의 오류와 보조 설명은 큰 글자에서도 줄바꿈한다.

현지 자정은 다음 달력 날짜로 계산한다. 앱 복귀 시 기기 날짜·시간대에 맞춰 다시 평가하며, 탭 진입 시 날짜가 바뀌었다면 갱신한다. 타이머는 앱 위젯이 제거될 때 취소한다. 같은 날짜의 탭 이동에서 불필요한 재조회를 하지 않도록 해 홈 스크롤 위치를 유지한다.

안내 확인 저장 실패는 성공으로 처리하지 않고 다음 실행 때 다시 나타날 수 있음을 알린다. 설정 조회 실패의 기본값과 상태는 기존 설정 Repository를 사용한다. 안내 상태가 계좌 초기화 여부를 결정하지 않는다.

추가 검증 범위:

- 원화 천 단위 표시, 0원·최대 금액, 쉼표 문법과 잘못된 입력 거부.
- 기분별 풀의 여러 메시지·바로 같은 메시지 반복 방지, 메시지 변경 후 잔고 불변.
- 마음 저장 중 추가 요청 차단, 동일 선택 중복 방지, 실패 시 이전 선택·문구 유지, 재시도 성공.
- 오늘의 마음 재조회, 다음 날짜에서 미선택 복원, 실제 자정 타이머 갱신과 정리.
- 계좌 편집 성공·입력 검증·미저장 이탈 확인·저장 실패 후 입력 유지와 재시도.
- 안내 저장 실패 시 앱 이용 유지 및 재시도 후 확인 상태 보관.
- 화면 폭 320·430·800과 글자 배율 1.0·1.3·2.0의 탭·홈 회귀 테스트.
- 폭 320과 글자 배율 2.0의 편집 오류·이탈 확인 흐름.
- 기존 DB 초기화·CRUD·파일 재연결·호환성 거부·오류 분류와 탭 스크롤 유지 회귀 검증.

각 플랫폼의 P0 통합 테스트는 실제 화면에서 메시지를 변경하고 마음을 선택한 뒤, 별칭과 잔고를 수정했다. 이후 앱의 전체 ProviderScope와 위젯 트리를 제거·재생성해 별칭·잔고·오늘의 기분·안내 확인 상태가 저장소에서 복원되는지 확인했다.

이 통합 테스트의 재생성은 운영체제 프로세스 강제 종료와 구분된다. 실제 프로세스 종료 후 DB 계좌 유지 검증은 Step 04에서 수행했고, P0 전체 종료·재실행 및 추가 안정화는 다음 Step 06의 검증 범위다. 테스트에서는 변경한 별칭·잔고·안내 값을 복원하고 추가 마음 기록을 삭제했다.

최종 날짜 갱신과 기본 글꼴 금액 폭 보완 후 단위·위젯 전체 검사와 양 플랫폼 빌드를 다시 통과했다. 통합 테스트 로그는 같은 P0 저장·복원 흐름의 플랫폼 검증 기록이다.
