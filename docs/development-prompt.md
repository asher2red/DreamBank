# 프로젝트 생성 프롬프트: DreamBank

## 1. 프로젝트 개요

**프로젝트명:** DreamBank

**한 줄 소개:** 돈 걱정이 많은 현실에서, 잠시나마 경제적 여유와 마음의 안정을 느낄 수 있는 가상의 은행 앱.

**핵심 슬로건:** A little escape from money worries.

DreamBank는 실제 금융 서비스가 아니다. 사용자가 가상의 은행 계좌와 잔고를 만들고, 넉넉한 자산을 가진 듯한 기분을 경험하며, 위로 메시지와 자신이 꿈꾸는 삶을 기록할 수 있는 감성 앱이다.

이 앱의 목적은 실제 재정 문제를 해결하는 것이 아니라, 사용자가 앱을 여는 짧은 순간이라도 부담을 내려놓고 기분이 조금 나아지도록 돕는 것이다.

## 2. 개발 원칙

- 우선 MVP를 구현한다. 초기부터 불필요한 복잡성을 추가하지 않는다.
- 실제로 실행하고 사용할 수 있는 기능을 구현한다.
- 디자인은 완성도 높은 상용 모바일 앱 수준을 목표로 한다.
- 기능을 추가하기 쉽도록 책임을 분리하고 유지보수 가능한 구조로 작성한다.
- 사용자가 요청하지 않은 대규모 기능이나 복잡한 백엔드는 추가하지 않는다.
- 구현 후 반드시 빌드와 테스트를 수행하고 오류를 수정한다.
- 작업을 완료했다고 보고하기 전에 실제 검증 결과를 확인한다.

## 3. 디자인 방향

### 전체 분위기

고급 프라이빗 뱅킹과 차분한 라이프스타일 앱의 분위기를 결합한다.

- 메인 색상: 딥 네이비 또는 블랙
- 포인트 색상: 은은한 골드
- 보조 색상: 아이보리, 차분한 회색
- 카드: 적절한 라운드와 여백, 절제된 그림자
- 타이포그래피: 잔고 숫자는 크고 명확하게, 본문은 편안하게
- 애니메이션: 잔고 숫자 등장, 카드 전환 등 필요한 부분에만 부드럽게 적용

과도한 장식, 번쩍이는 효과, 복잡한 그래프, 전형적인 대시보드 UI는 피한다.

첫 화면을 보는 순간 사용자가 '나에게도 이만큼의 여유가 있다면 좋겠다'고 느끼게 만드는 것이 목표다.

### 앱 아이콘 및 로고

DreamBank라는 이름에 어울리는 간결하고 고급스러운 로고를 사용한다. 은행 건물, 금고, 별, 꿈을 상징하는 요소를 절제해서 활용한다.

## 4. MVP 핵심 기능

### 기능 1. 나만의 가상 계좌

사용자가 DreamBank에 들어오면 자신의 가상 계좌와 잔고를 볼 수 있다.

초기 기본값:

- 계좌명: 나의 여유 계좌
- 가상 잔고: ₩1,000,000,000
- 통화: KRW
- 계좌 별칭은 사용자가 수정할 수 있다.

잔고는 실제 자산이 아닌 가상 잔고다. 사용자가 쉽게 알아볼 수 있도록 '가상 잔고' 또는 '상상 속 자산'이라는 표시를 제공한다.

실제 은행 계좌 연결, 실제 입출금, 금융 상품 판매 기능은 구현하지 않는다.

### 기능 2. 오늘의 여유

메인 화면에 오늘의 짧은 위로 메시지를 표시한다.

메시지 예시:

- 오늘은 당장 모든 답을 찾지 않아도 괜찮아요.
- 오늘의 당신에게 휴식 100만 원을 지급합니다.
- 조금 쉬어도 괜찮아요. 당신은 충분히 노력했어요.
- 돈 걱정 없이 하루를 보낼 수 있다면, 오늘은 무엇을 하고 싶나요?

요구사항:

- 여러 메시지를 준비한다.
- 버튼을 누르면 다른 메시지를 볼 수 있다.
- 메시지는 잔고와 시각적으로 조화를 이루도록 표시한다.
- 매일 방문을 강요하거나 연속 출석을 요구하지 않는다.

### 기능 3. 오늘의 마음 잔고

사용자가 현재 기분을 간단하게 선택할 수 있다.

선택 항목:

- 조금 지쳤어요.
- 그냥 그래요.
- 오늘은 괜찮아요.
- 기분이 좋아요.

선택한 기분에 따라 위로 메시지를 다르게 표시한다.

사용자가 선택을 건너뛰어도 앱의 다른 기능을 제한하지 않는다. 기록은 로컬에 저장한다.

### 기능 4. 꿈 보관함

사용자가 돈 걱정이 없다면 하고 싶은 일을 기록할 수 있다.

예시:

- 부모님께 편안한 집을 선물하기
- 가족과 한 달 동안 여행하기
- 좋아하는 취미에 충분한 시간 쓰기
- 아무 일정 없이 쉬는 하루 보내기

기능:

- 꿈 추가
- 꿈 수정
- 꿈 삭제
- 꿈 목록 보기
- 선택적으로 예상 비용 입력

예상 비용은 실제 지출이나 계좌 잔고에 영향을 주지 않는 가상의 값이다.

### 기능 5. 미래의 나에게 보내는 편지

사용자가 미래의 자신에게 메시지를 작성할 수 있다.

기능:

- 편지 작성 및 수정
- 작성일 저장
- 원하는 공개 날짜 설정
- 편지 목록 확인
- 날짜가 도래하면 편지를 열람할 수 있도록 표시

초기 버전에서는 로컬 저장만으로 구현한다. 복잡한 푸시 알림이나 서버 기반 예약 발송은 추가하지 않는다.

### 기능 6. 가상 계좌 카드 공유

사용자가 자신의 가상 계좌를 예쁜 카드 이미지로 만들어 공유할 수 있도록 한다.

카드에 표시할 정보:

- DreamBank 로고
- 사용자가 설정한 계좌 별칭
- 가상 잔고
- 짧은 문구

예시:

- 퇴사 허가 통장 — ₩1,000,000,000
- 평생 월요병 면제 통장 — ₩1,000,000,000
- 아무것도 안 해도 되는 통장 — ₩1,000,000,000

실제 은행 계좌나 잔고로 오인되지 않도록 카드에 '가상 잔고' 또는 이에 준하는 표시를 포함한다.

기본 공유 기능은 운영체제의 공유 기능을 활용한다. 서버, 친구 목록, 팔로우, 채팅은 구현하지 않는다.

## 5. 화면 구성

하단 탭 내비게이션을 사용한다.

### 홈

- DreamBank 로고
- 인사말
- 가상 잔고 카드
- 오늘의 여유 메시지
- 오늘의 마음 잔고
- 꿈 보관함으로 이동하는 진입점

### 꿈 보관함

- 저장한 꿈 목록
- 꿈 추가 버튼
- 꿈별 상세 내용 및 예상 비용

### 미래의 편지

- 작성한 편지 목록
- 새 편지 작성
- 열람 가능한 편지와 아직 열 수 없는 편지 구분

### 내 계좌

- 계좌 별칭 수정
- 가상 잔고 표시
- 공유용 카드 미리보기
- 앱 정보 및 설정

화면은 작은 모바일 기기에서도 자연스럽게 동작해야 한다. 중요한 정보가 잘리거나 하단 탭과 겹치지 않도록 한다.

## 6. 데이터 저장

초기 MVP는 로컬 우선으로 구현한다.

- 계좌 별칭 및 사용자 설정
- 가상 잔고 설정
- 마음 잔고 선택 기록
- 꿈 보관함 데이터
- 미래의 편지 데이터

앱을 종료하고 다시 실행해도 저장된 정보가 유지되어야 한다.

데이터 저장 방식은 현재 프로젝트의 기술 스택에 맞는 안정적인 로컬 저장소를 선택한다. 민감한 개인정보는 불필요하게 수집하지 않는다.

백엔드, 회원가입, 로그인, 클라우드 동기화는 이번 MVP 범위에서 제외한다.

## 7. 우선순위

P0 — MVP 필수:

1. 앱 실행 및 기본 내비게이션
2. 가상 계좌와 잔고 화면
3. 오늘의 여유 메시지
4. 오늘의 마음 잔고
5. 로컬 데이터 저장

P1 — 핵심 경험 확장:

6. 꿈 보관함
7. 미래의 나에게 보내는 편지
8. 가상 계좌 카드 이미지 생성 및 공유

P2 — 추후 검토:

- 잔고 수준별 테마 및 라이프스타일
- 추가 카드 디자인
- 클라우드 백업
- 선택적인 알림 기능

P2 기능은 이번 MVP에서 구현하지 않는다.

## 8. 개발 진행 절차

작업을 시작하기 전에 현재 개발 환경과 프로젝트 상태를 확인한다.

아직 프로젝트가 없다면 적절한 기술 스택을 선택하고 기본 프로젝트를 생성한다. 이미 프로젝트가 있다면 기존 구조와 설정을 우선 존중한다.

그다음 아래 순서로 진행한다.

1. 개발 환경 및 프로젝트 구조 확인
2. 기술 스택 결정 및 근거 설명
3. 핵심 화면과 데이터 모델 설계
4. 프로젝트 기본 구조 구현
5. P0 기능 구현
6. P0 빌드 및 테스트
7. P1 기능 구현
8. 전체 빌드 및 테스트
9. 오류 수정 및 최종 검증
10. 실행 방법, 구현 기능, 남은 작업 보고

중요한 결정이 필요한 경우 현재 환경과 프로젝트 목적에 가장 적합한 선택을 하되, 불필요하게 사용자에게 사소한 결정을 반복해서 묻지 않는다.

## 9. 완료 조건

- 앱을 실행할 수 있다.
- 홈 화면에서 가상 잔고와 오늘의 여유 메시지를 확인할 수 있다.
- 마음 상태를 선택하고 그에 맞는 메시지를 확인할 수 있다.
- 꿈과 편지를 생성·수정·삭제할 수 있다.
- 앱을 재실행해도 저장된 데이터가 유지된다.
- 가상 계좌 카드를 생성하고 공유할 수 있다.
- 실제 금융 서비스로 오인하게 만드는 표현이나 기능이 없다.
- 주요 기능의 테스트와 빌드 검증을 완료한다.

먼저 현재 개발 환경을 조사하고, 가장 적합한 기술 스택과 구현 계획을 짧게 제시한 다음 실제 프로젝트 구현을 시작하라. 단순한 설계 문서만 작성하고 끝내지 말고, 실행 가능한 결과물을 만들어라.
