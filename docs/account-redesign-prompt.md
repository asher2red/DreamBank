# DreamBank 내 계좌 화면 개편 개발 프롬프트

## 1. 작업 목표

현재 DreamBank의 **내 계좌** 화면을 클래식한 은행 앱처럼 익숙하고 신뢰감 있는 화면으로 개편하라. 사용자가 자신의 넉넉한 잔고를 확인하고 잠시 여유를 느끼는 경험이 중심이다.

이번 작업은 기존 Flutter 프로젝트의 내 계좌 화면을 개선하는 작업이다. 새로운 앱이나 백엔드를 만들지 말고 기존 Riverpod·go_router·Repository·로컬 저장 구조와 디자인 자산을 활용하라.

## 2. 화면 분위기

- 편안하고 고급스러운 프라이빗 뱅킹 분위기를 유지한다.
- 네이비·샴페인 골드·아이보리, 기존 별 로고와 계좌 카드 이미지를 사용한다.
- 계좌명, 큰 잔고, 주요 금융 동작 버튼을 한눈에 읽을 수 있도록 정돈한다.
- 익숙한 은행 앱의 정보 구조와 버튼 배치를 참고하되 특정 은행의 로고나 화면을 복제하지 않는다.
- 메인 화면은 차분하고 진지하게 구성하고, 유머는 버튼을 눌렀을 때의 팝업에서 표현한다.
- 번쩍이는 효과, 과장된 장식, 만화 같은 기본 화면, 복잡한 그래프는 추가하지 않는다.

## 3. 내 계좌 화면 구성

위에서 아래로 다음 정보를 배치한다.

1. **화면 제목:** 내 계좌
2. **계좌 영역:** 사용자가 설정한 계좌 별칭, DreamBank 브랜드, 크게 표시한 실제 저장 잔고, 통화 KRW
3. **주요 동작:** 입금 / 출금 / 송금
4. **관리 영역:** 계좌 설정 수정, DreamBank 소개

계좌 카드는 실물 금융 카드의 장식보다 계좌 요약에 가깝게 구성한다. 별칭과 잔고 사이의 위계를 분명히 하고, 금액은 천 단위 구분과 원화 기호를 사용한다. 계좌 별칭이나 잔고를 수정하면 기존과 같이 홈과 내 계좌에 반영되어야 한다.

실제로 발급하지 않은 은행 계좌번호, 실명 인증 배지, 예금자 보호 표시, 금융기관 인증 문구는 추가하지 않는다. 거래 내역이 구현되어 있지 않다면 임의의 거래 내역이나 성공 이력을 채워 넣지 않는다.

## 4. 경고성 문구 정리

**내 계좌 화면에서는 “실제 금융 자산이 아니에요”, “이것은 진짜 계좌가 아닙니다” 같은 경고성 문장을 제거한다.** 해당 문구가 반복되거나 잔고 확인 경험을 방해하지 않게 한다.

현재 공통 `AccountCard`가 홈과 내 계좌에서 함께 쓰이므로, 화면별 표시 정책을 분리해 내 계좌에 필요한 변경을 적용한다. 홈·공유 카드·앱 소개의 안내를 함께 삭제하는 변경으로 확대하지 않는다. 앱 소개의 서비스 성격 및 로컬 데이터 안내는 유지한다.

내 계좌의 잔고 명칭은 `계좌 잔고` 또는 `Dream Money 잔고`처럼 자연스럽게 표시한다. 설명을 제거한 자리에 다른 경고 배너를 추가하지 않는다.

## 5. 입금·출금·송금 버튼

세 버튼은 금융 앱에서 익숙한 아이콘과 명확한 텍스트 라벨을 함께 사용한다.

- 입금: 계좌로 들어오는 방향을 나타내는 아이콘
- 출금: 계좌에서 나가는 방향을 나타내는 아이콘
- 송금: 보내기 또는 이동을 나타내는 아이콘

계좌 카드 바로 아래에서 세 동작을 같은 중요도로 보여준다. 터치 영역은 최소 48×48 logical px로 하고, 작은 화면이나 큰 글자에서는 버튼 라벨이 잘리지 않도록 배치를 조정한다. 회색 비활성 버튼이 아니라 **누를 수 있는 버튼**으로 제공한다.

탭 시 해당 기능의 안내 팝업을 표시한다. 금액 입력·계좌번호 입력·연락처 접근·은행 연결 화면으로 이동하지 않는다. 실제 또는 가상의 잔고 변경, 거래 기록 생성, 외부 네트워크 요청, 결제·송금 처리는 수행하지 않는다.

## 6. 코믹한 안내 팝업

기본 메시지는 **“Dream Money는 아직 해당 기능을 제공하지 않아요.”**다. 사용자가 버튼을 눌렀을 때 기능을 준비 중임을 즉시 이해하고 가볍게 웃을 수 있어야 한다.

팝업은 브랜드와 어울리는 네이비·아이보리·골드 톤을 유지하고 작은 아이콘 하나로 개성을 준다. 큰 만화 이미지나 추가 AI 이미지 제작은 필수가 아니다. 유머는 짧고 따뜻하게 표현하고, 사용자의 실제 경제적 어려움이나 잔고를 놀리지 않는다.

### 입금 팝업

**제목:** 입금 창구는 잠시 꿈꾸는 중

**본문:**

> Dream Money는 아직 입금 기능을 제공하지 않아요.
>
> 담당 직원이 구름 위에서 낮잠 중이에요. 마음의 여유는 언제든 입금해 주세요.

**확인 버튼:** 여유는 입금 완료

확인 버튼 문구는 감성적인 농담이며, 잔고를 변경하거나 금전 입금 성공 표시를 추가하지 않는다.

### 출금 팝업

**제목:** 현금보다 휴식이 먼저예요

**본문:**

> Dream Money는 아직 출금 기능을 제공하지 않아요.
>
> ATM이 오늘은 휴가를 냈어요. 대신 깊은 숨을 한 번 꺼내 드릴게요.

**확인 버튼:** 후우, 잘 받았어요

### 송금 팝업

**제목:** 송금 담당 구름을 찾는 중

**본문:**

> Dream Money는 아직 송금 기능을 제공하지 않아요.
>
> 마음은 보낼 수 있지만 돈을 배달할 구름은 아직 출근 전이에요.

**확인 버튼:** 마음만 보낼게요

### 팝업 공통 동작

- 확인 버튼은 팝업을 닫고 현재 내 계좌 화면으로 돌아간다.
- 시스템 뒤로가기와 바깥 영역 탭으로도 닫을 수 있다.
- 빠르게 반복해서 눌러도 팝업이 여러 개 쌓이지 않도록 한다.
- 닫은 뒤 같은 버튼 또는 다른 버튼을 다시 누를 수 있어야 한다.
- 어떤 버튼을 눌러도 계좌 별칭·잔고·마음 기록·꿈·편지 데이터는 바뀌지 않는다.
- 제목·본문·확인 버튼이 큰 글자와 작은 화면에서도 잘리지 않도록 팝업 본문에 스크롤을 허용한다.
- 접근성 읽기 순서와 확인 버튼 라벨을 제공한다.

## 7. 기존 구조에 적용하는 방법

- `AccountScreen`의 계좌 요약·동작·관리 영역 책임을 구분한다.
- `AccountCard`에는 필요한 경우 화면별 표시 옵션을 추가한다. 경고성 안내 표시의 기본값은 기존 사용처와 호환되게 유지하고, 내 계좌에서만 해제한다.
- 입금·출금·송금 동작은 하나의 작은 공통 컴포넌트 또는 명확한 enum으로 관리해 팝업 UI를 중복 작성하지 않는다.
- 잔고는 기존 `accountProvider`와 Repository의 값을 그대로 사용한다.
- 코믹 팝업은 Presentation 계층에서 처리하고 금융 기능용 Repository나 가짜 거래 모델은 만들지 않는다.
- 현재 구현하지 않은 카드 공유 기능은 완료된 기능처럼 표시하지 않는다. 준비 상태 문구는 필요하면 관리 영역의 낮은 우선순위로 정리한다.
- 화면에 개발 단계, 패키지 이름, 내부 구현 설명을 노출하지 않는다.

## 8. 검증 및 완료 조건

1. 내 계좌에서 저장된 별칭과 잔고를 정확히 확인할 수 있다.
2. 내 계좌에 “실제 금융 자산이 아니다”라는 경고성 문구가 반복 표시되지 않는다.
3. 입금·출금·송금 버튼을 각각 누르면 해당 제목과 안내 문구의 팝업이 표시된다.
4. 확인·바깥 영역 탭·뒤로가기로 팝업을 닫고 다시 사용할 수 있다.
5. 빠른 반복 탭에도 팝업은 하나만 표시된다.
6. 버튼 실행 전후 계좌 잔고와 저장 데이터가 동일하다.
7. 계좌 설정 수정과 홈 반영이 기존처럼 동작한다.
8. 홈·앱 소개·향후 공유 카드의 별도 안내 정책이 의도치 않게 바뀌지 않는다.
9. 폭 320의 화면과 글자 배율 2.0에서도 금액·버튼·팝업을 읽고 조작할 수 있다.
10. 정적 분석과 관련 위젯 테스트를 수행하고 Android·iOS 빌드 결과를 구분해 기록한다.

완료 후 변경 화면, 테스트·빌드 결과, 알려진 제한을 문서로 남겨라. 현재 요청 단계는 이 개발 프롬프트 작성이며, 실제 코드 구현은 별도 실행 요청에 따라 진행한다.
