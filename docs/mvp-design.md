# DreamBank MVP 화면 및 동작 설계

작성일: 2026-10-29 (Asia/Seoul) · 단계: Step 02

기준: [기능 명세](development-prompt.md), [기술 스펙](development-technical-spec.md), [개발 계획](development-plan.md).
이 문서의 규칙은 구현 기준이며 구현·기기 검증 완료를 의미하지 않는다. 저장 규칙은 [데이터 모델](data-model.md), 인수 조건은 [검증 대응표](acceptance-criteria.md)를 따른다.

## 1. 확정한 MVP 범위

- 한국어 UI, KRW 단일 통화, 기본 가상 잔고 10억 원. 별칭과 가상 잔고를 내 계좌에서 수정할 수 있다.
- 다크 테마 한 종류로 시작한다. 추가 테마·테마 선택 UI는 구현하지 않는다.
- 계정·로그인·서버 없이 앱 내부 DB와 설정 저장소를 사용한다. 온보딩은 강제하지 않고 홈에서 가상 서비스 안내를 제공한다.
- 꿈·편지·마음 기록의 샘플 데이터를 자동 생성하지 않는다. 예시 문구는 입력 힌트로만 사용한다.
- 공개일 잠금은 열람 화면의 표시 규칙이다. 작성자는 공개 전에도 명시적인 편집 동작으로 내용을 수정할 수 있다. 암호화·시계 조작 방지 기능은 제공하지 않는다.
- P0에서는 4개 탭을 구성하되 꿈·편지 탭은 안내 상태로 둔다. 저장 기능이 없는 버튼을 동작하는 것처럼 노출하지 않는다. P1에서 각 기능을 연결한다.

## 2. 화면 이동과 구성

앱 초기화가 성공하면 `/home`으로 진입한다. 초기화 실패 화면은 재시도만 제공하며 빈 계좌를 정상 계좌처럼 표시하지 않는다. 탭은 홈 / 꿈 보관함 / 미래의 편지 / 내 계좌 순서다. 탭별 목록 스크롤을 세션 동안 유지하고 앱 재실행 시 홈으로 시작한다.

| 경로 | 화면 및 구성 | 주요 동작 |
|---|---|---|
| `/home` | 로고, 인사말, 별칭·가상 잔고 카드, 오늘의 여유, 마음 선택, 꿈 진입 카드 | 메시지 변경, 마음 저장, 계좌·꿈 탭으로 이동 |
| `/dreams` | 제목, 꿈 목록, 꿈 추가 버튼 | 항목 상세, 새 꿈 작성 |
| `/dreams/new` | 제목·설명·예상 비용 입력 폼 | 저장 후 해당 꿈 상세로 대체 이동 |
| `/dreams/:id` | 제목, 설명, 선택 비용, 수정·삭제 | 편집 또는 삭제 확인 |
| `/dreams/:id/edit` | 기존 값이 채워진 폼 | 저장 후 상세로 복귀 |
| `/letters` | 제목, 편지 목록, 새 편지 버튼 | 공개 상태에 맞는 상세 화면 |
| `/letters/new` | 제목·내용·공개 날짜 폼 | 저장 후 해당 편지 상세로 대체 이동 |
| `/letters/:id` | 제목, 작성일, 공개 상태, 공개된 내용 또는 공개 예정 안내 | 편집·삭제 |
| `/letters/:id/edit` | 내용 및 날짜 편집 폼 | 저장 후 상세로 복귀 |
| `/account` | 계좌 정보, 편집 진입점, 공유 카드 미리보기·버튼, 앱 안내 | 계좌 수정, OS 공유, 앱 정보 |
| `/account/edit` | 별칭·가상 잔고 입력 폼 | 저장 후 내 계좌로 복귀 |
| `/account/about` | 슬로건, 가상 서비스·로컬 저장·편지 공개 규칙·앱 버전·라이선스 안내 | 뒤로 이동 |

탭 루트는 하단 탭을 표시한다. 작성·편집·상세·정보 화면은 루트 내비게이터 위에 열어 하단 탭을 숨기고 뒤로가기를 제공한다. 새 항목 저장 후 뒤로가면 목록으로 돌아가며, 편집 저장 후에는 이전 상세로 돌아간다. `new`와 `:id`는 라우팅에서 구분한다.

존재하지 않거나 삭제된 ID는 “기록을 찾을 수 없어요”와 목록으로 이동 버튼을 표시한다. 폼에 변경이 있을 때 뒤로가기·닫기를 누르면 “작성을 그만둘까요?”와 계속 작성 / 버리기를 제공한다. 임시 입력 자동 저장은 하지 않는다. 저장 중에는 중복 제출과 화면 닫기를 막으며 완료 또는 오류 후 해제한다.

## 3. 홈과 마음 잔고

홈 콘텐츠는 세로 스크롤이며 잔고를 첫 번째 주요 카드로 배치한다. 기본 인사말은 “잠시, 마음에 여유를 주세요.”다. 잔고 아래에 “가상 잔고 · 실제 금융 자산이 아니에요”를 표시한다.

마음 선택은 선택적이며 팝업이나 강제 설문을 띄우지 않는다. 최신 기록이 기기 현지 날짜 기준 오늘일 때만 오늘의 선택으로 복원한다. 이전 날짜 기록은 유지하되 새 날짜의 홈에서는 미선택과 공통 메시지로 시작한다.

| 저장 값 | 표시 문구 | 메시지 풀 예시 |
|---|---|---|
| `tired` | 조금 지쳤어요. | 조금 쉬어도 괜찮아요. 당신은 충분히 노력했어요. / 오늘은 당장 모든 답을 찾지 않아도 괜찮아요. / 오늘의 당신에게 휴식 100만 원을 지급합니다. |
| `neutral` | 그냥 그래요. | 특별한 일이 없는 하루도 괜찮아요. / 오늘은 마음이 가는 속도로 걸어가요. / 지금은 잠시 숨을 고르는 시간이에요. |
| `okay` | 오늘은 괜찮아요. | 오늘의 편안함을 조금 더 누려보세요. / 나를 위한 작은 여유를 골라볼까요? / 돈 걱정 없이 하루를 보낸다면 무엇을 하고 싶나요? |
| `happy` | 기분이 좋아요. | 오늘의 좋은 마음을 충분히 즐겨요. / 당신이 꿈꾸는 하루를 상상해 보세요. / 이 기분을 미래의 나에게 남겨볼까요? |
| 미선택 | 선택 없이 이용 가능 | 오늘은 당장 모든 답을 찾지 않아도 괜찮아요. / 돈 걱정 없이 하루를 보낼 수 있다면, 오늘은 무엇을 하고 싶나요? / 오늘의 당신에게 휴식 100만 원을 지급합니다. |

각 풀은 최소 3개로 유지한다. 최초 표시는 현지 날짜의 연·월·일을 조합한 값으로 풀의 인덱스를 선택한다. “다른 메시지”는 해당 풀의 다음 인덱스로 순환하므로 바로 같은 문구가 반복되지 않는다. 메시지 인덱스는 세션 상태이며 DB에 저장하지 않는다. 자산 증감·출석 보상은 발생하지 않는다.

새 마음 선택은 DB 저장 성공 후 선택 표시와 해당 풀의 메시지에 반영한다. 동일 선택을 다시 누르면 쓰기를 생략한다. 다른 선택은 새 기록으로 추가하며 저장 중에는 선택 버튼을 잠근다. 실패 시 이전 선택·메시지를 유지하고 재시도를 제공한다. 자정·앱 재개·홈 진입 시 날짜와 오늘의 기록을 재평가한다.

## 4. 입력 및 CRUD 규칙

텍스트 앞뒤 공백을 제거한 뒤 검증한다. 길이는 사용자가 인식하는 문자 단위(grapheme cluster)로 센다. 한글·이모지를 중간에서 자르지 않고 초과 입력은 오류로 안내한다. 제목·별칭은 한 줄, 본문은 줄바꿈을 허용한다.

| 필드 | 규칙 | 오류 안내 |
|---|---|---|
| 계좌 별칭 | 필수, 1~30자 | 계좌 이름을 1~30자로 입력해 주세요. |
| 가상 잔고 | 필수, 정수 0~999,999,999,999원 | 0~999,999,999,999원 사이의 정수를 입력해 주세요. |
| 꿈 제목 | 필수, 1~80자 | 꿈의 제목을 1~80자로 입력해 주세요. |
| 꿈 설명 | 선택, 0~2,000자 | 설명은 2,000자까지 입력할 수 있어요. |
| 꿈 예상 비용 | 선택, 정수 0~999,999,999,999원 | 예상 비용을 원 단위 정수로 입력해 주세요. |
| 편지 제목 | 필수, 1~80자 | 편지 제목을 1~80자로 입력해 주세요. |
| 편지 내용 | 필수, 1~10,000자 | 편지 내용을 1~10,000자로 입력해 주세요. |
| 공개 날짜 | 선택, 현지 달력 날짜 | 올바른 공개 날짜를 선택해 주세요. |

금액 필드에는 원 단위 숫자와 올바른 천 단위 쉼표만 허용한다. 예: `1000000`, `1,000,000`은 허용하고 `1,00`, `1.5`, 음수·지수 표기·통화 기호는 오류 처리한다. 빈 비용은 `null`, `0`은 명시적인 0원으로 구분한다. 표시는 `₩`와 천 단위 쉼표를 사용한다. 계좌 통화 변경 UI는 없다.

꿈과 편지는 저장일 내림차순이 아닌 **최근 수정일 내림차순, ID 내림차순**으로 정렬한다. 제목 중복은 허용한다. 꿈의 비용은 표시용이며 합계·결제·계좌 차감은 없다. 삭제는 확인 대화상자 후 DB 성공 시 목록으로 복귀하며 영구 삭제된다. 실패 시 화면과 데이터 표시를 유지한다.

## 5. 편지 공개 규칙

- 공개일은 시간·시간대가 없는 `YYYY-MM-DD` 달력 날짜다. 현재 기기 현지 날짜가 공개일 이상이면 공개한다. 미지정이면 즉시 공개한다.
- 날짜 선택 범위는 작성 또는 편집 시 오늘부터 2100-12-31까지다. 기존의 과거 공개일은 그대로 유지할 수 있다. “날짜 지정 안 함”으로 해제할 수 있다. 기기 날짜가 상한 이후라면 날짜 지정 대신 즉시 공개만 허용한다.
- 작성 시각은 편집해도 유지하고, 수정 시각만 갱신한다. 공개일 변경에 따라 공개된 편지를 다시 잠글 수 있다.
- 목록에는 제목, 작성일, `열어볼 수 있어요` 또는 `YYYY.MM.DD 공개 예정`을 표시한다. 목록의 본문 미리보기는 모든 편지에서 생략한다.
- 잠긴 상세 화면은 본문을 렌더링하거나 접근성 트리에 노출하지 않는다. “공개일 전에도 편집 화면에서 내용을 수정할 수 있어요”를 표시하고 편집 진입 시 기존 본문을 제공한다.
- 앱 정보에 “공개 날짜는 기기의 날짜를 기준으로 해요. 편지 잠금은 보안 잠금이 아니며 작성자는 언제든 편집할 수 있어요.”를 표시한다.
- 앱 재개·상세 진입·현지 자정에 상태를 다시 계산한다. 현지 자정 타이머는 다음 달력 날짜로 계산하고 고정 24시간을 더하지 않는다. 현재 시각 제공 함수를 주입해 테스트한다.
- 시간대 또는 기기 날짜 변경으로 다시 잠길 수 있다. 이를 별도 영구 공개 상태로 저장하지 않는다. 서버 시각·예약 발송·알림은 사용하지 않는다.

## 6. 화면 상태와 실패 처리

| 대상 | 로딩·저장 중 | 빈 상태 | 실패 및 복구 |
|---|---|---|---|
| 초기화·계좌 | 중립 로딩 표시, 가짜 기본 잔고 노출 금지 | 정상 초기화에서 기본 계좌 생성 | “계좌를 불러오지 못했어요”와 재시도; DB 초기화 금지 |
| 홈 마음 기록 | 계좌와 독립 조회, 선택 잠시 비활성 | 미선택·공통 메시지 | 기록 조회 실패 표시와 재시도, 계좌·다른 탭 이용 가능 |
| 꿈·편지 목록 | 첫 조회 로딩, 기존 데이터 재조회는 데이터 유지 | 안내와 새 기록 버튼 | 첫 조회 오류 화면 또는 기존 목록+오류 안내, 재시도 |
| 상세 | 조회 중 표시 | 없는 항목 안내 | 조회 오류와 재시도 |
| 입력 폼 | 저장 버튼 진행 표시, 제출 잠금 | 입력 힌트 | 필드 오류 또는 저장 실패 안내; 입력 유지 |
| 삭제 | 확인 후 진행 표시·중복 삭제 잠금 | 해당 없음 | 삭제 실패 안내, 기존 상세 유지 |
| 공유 | 이미지 생성·전달 중 버튼 잠금 | 해당 없음 | 생성 실패와 공유 실패 구분, 재시도; 취소는 정상 종료 |

성공 피드백은 실제 저장 성공 이후에만 표시한다. 오류 로그는 동작명·오류 분류·개발용 스택으로 제한하고 SQL 바인딩 값, 편지·꿈 내용, 별칭을 출력하지 않는다. 화면용 메시지는 내부 예외 문자열과 분리한다.

## 7. 디자인 토큰과 접근성

아래는 구현 시작값이다. 색 대비와 기기 렌더링 검증 후 공통 토큰에서 조정한다. 개별 위젯에 색상을 반복 하드코딩하지 않는다.

| 종류 | 토큰과 값 |
|---|---|
| 색상 | primary `#142238`, background `#0B111B`, surface `#162131`, elevated `#202E41` |
| 강조·문자 | accent `#D4B77A`, textPrimary `#F5F1E8`, textSecondary `#B7C0CE`, error `#FFB4AB` |
| 글자 크기 | 잔고 40, 화면 제목 24, 카드 제목 18, 본문 16, 보조 14 logical px |
| 간격 | 4, 8, 12, 16, 24, 32; 화면 좌우 기본 20 |
| 모서리 | 카드 24, 입력·버튼 12 |
| 그림자 | 검정 alpha 0.16, blur 16, offset (0, 6); 과도한 중첩 금지 |
| 애니메이션 | 상태 변화 180ms, 카드 진입 240ms; 반복 장식 없음 |

금색 채움 버튼에는 어두운 글자를 사용한다. 글꼴은 플랫폼 시스템 글꼴로 시작해 네트워크 폰트 다운로드를 하지 않는다. 로고는 단순한 별 모티프와 DreamBank 워드마크를 공통 벡터/코드 자산으로 구현한다.

- 일반 텍스트 대비 4.5:1 이상, 큰 텍스트·주요 비문자 요소 3:1 이상을 검증 목표로 삼는다. 실제 준수 여부는 구현 검증에서 확인한다.
- 터치 영역 최소 48×48 logical px, 선택·공개 상태는 색과 함께 문구·아이콘으로 표현한다.
- 화면 폭 320~430과 넓은 화면, 글자 배율 1.0·1.3·2.0에서 검증한다. 넓은 화면 콘텐츠 폭은 최대 600으로 제한한다.
- 잔고는 통화 기호를 포함한 전체 값을 유지한다. 큰 글자에서는 크기를 강제로 줄이지 않고 필요하면 금액 영역의 가로 스크롤을 허용하며 전체 금액 접근성 라벨을 제공한다.
- 카드와 폼 높이는 내용에 따라 늘어나고 마음 선택은 Wrap으로 배치한다. 키보드·하단 안전 영역을 포함한 스크롤 여백을 둔다.
- 아이콘 버튼에 라벨, 폼에 필드 설명과 오류 연결, 화면에 논리적인 읽기 순서를 제공한다. 시스템의 애니메이션 감소 설정을 존중한다.

## 8. 공유 카드

내 계좌 미리보기와 이미지 생성은 동일한 카드 위젯과 같은 계좌 스냅샷을 사용한다. 내용은 DreamBank 로고, 전체 별칭, 잔고, “A little escape from money worries.”, “가상 잔고 · 실제 금융 자산이 아닙니다”다. 꿈·편지·마음 기록은 포함하지 않는다.

내보내기는 폭 360 logical px, 콘텐츠 기반 높이, pixelRatio 3의 PNG로 시작한다. 별칭은 줄바꿈하고 자르지 않는다. 미리보기는 같은 캔버스를 화면에 맞춰 축소해 이미지와 내용·배치를 일치시킨다. 공유 이미지는 고정 타이포그래피를 사용하고, 화면 미리보기에는 전체 정보의 접근성 설명을 제공한다.

순서: 계좌 스냅샷 → 카드 렌더링 완료 → PNG 생성 → 임시 전용 디렉터리 저장 → OS 공유. 공유 중 편집으로 값이 바뀌어도 현재 이미지에는 캡처한 스냅샷을 유지한다. 공유 어댑터와 이미지 생성 서비스를 분리한다.

공유 종료 직후 파일을 지우지 않는다. 다음 공유 또는 앱 시작 때 전용 디렉터리의 24시간 초과 파일만 정리하고 현재 사용 파일은 제외한다. 정리 실패는 공유 실패로 처리하지 않으며 사용자 텍스트가 없는 오류만 기록한다. 취소 후 성공 메시지를 표시하지 않는다.

## 9. 구현 책임과 단계 경계

UI → 기능 Notifier/Controller → Repository → Drift 또는 설정 저장소 순으로 의존한다. DB 생성·마이그레이션·초기 계좌 생성을 UI와 분리한다. 통화 형식, 입력 검증, 메시지 순환, 날짜 공개 판정은 순수 로직으로 테스트한다. 폼과 애니메이션 상태는 로컬 위젯 상태로 유지한다.

Step 02에서는 설계와 인수 조건을 확정했다. 앱 생성은 Step 03, 저장소 구현은 Step 04에서 수행한다. Step 01의 Flutter SDK·doctor 미완료 사항은 유지되며 실행 단계 전에 보완해야 한다.
